# The two SCORING SELECTORS for the rows in
# scripts/fixtures/lock_snap_records.txt -- the SAME records, in the same
# order, line for line. Read by scripts/lock_snap_replay.py, which requires
# that alignment and refuses to publish a figure if the two files have drifted
# apart.
#
# WHY A SECOND FILE RATHER THAN TWO MORE COLUMNS IN THE FIRST. Neither column
# here is an input to gatedRate. step_type selects which seconds are WORK and
# enhanced_speed is the independent witness the slow-boat count is taken
# against; letting either sit in the replay file would make a decision figure
# depend on a series the decision never reads. lock_guard_speed.txt exists for
# exactly this reason and says so.
#
# FORMAT
#   ROW <key> <label>               starts a row; same keys, same order
#   CTX <step_type> <enhanced_speed>
#                                   one recorded second; step_type is the
#                                   integer code, enhanced_speed is m/s
#   Lines beginning with # and blank lines are ignored.
#
# PROVENANCE:
#   values         step_type       developer field id 17 of record messages
#                                  (FIT global message 20)
#                  enhanced_speed  the NATIVE record field 73, m/s, 3 decimal
#                                  places, which is the precision the file
#                                  carries
#   work laps      a work lap is a maximal contiguous run of records whose
#                  step_type is 2. On i183553852 that is 8 laps and 1443
#                  seconds. The other two rows have NO work laps here; see the
#                  absence note.
#
# ABSENCE IS `-`, AND IT IS NOT ZERO. This file needs an absence marker where
# its companion does not, and the two columns are absent for different reasons:
#
#   step_type is absent on ALL 3002 records of i178249719 and ALL 2276 of
#   i174014735. Those two rows were recorded before developer field 17 existed;
#   the field is not empty in them, it is not there. So no work-lap figure can
#   be computed for either, and lock_snap_replay.py reports that rather than
#   substituting the whole row for its work laps.
#
#   enhanced_speed is absent on 24 records of i183553852 and 1 of i178249719,
#   and 0.000 m/s IS A REAL READING on the rest -- a stopped boat. A missing
#   speed is therefore NOT written as 0: 5 of the 24 absent-speed records of
#   i183553852 read above 25 spm, and counting them as "slow boat" would put
#   the row's slow-boat total at 364 instead of 359 by rendering an absence as
#   a value. lock_snap_replay.py excludes them and prints both counts.
